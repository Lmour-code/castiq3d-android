# CastIQ 3D — Native Android (Stage 1)

Part of the Structural Twin / LayupIQ / ForceIQ / GaitIQ ecosystem.
This is the **3D geometry and measurement layer**, built as a real Android Studio project.

## What this build actually is

This is **Stage 1 only**, per the directive's own staged ordering: the native 3D measurement
engine, proven against a known test model, before any camera scanning or reconstruction work
begins.

**Implemented and real (not simulated):**
- OpenGL ES 2.0 3D viewport: rotate (1-finger drag), pan (2-finger drag), pinch zoom, reset view
- Loads a real triangle mesh from `assets/models/sample_afo_cast.obj` (a synthetic AFO-shaped
  test solid generated for this build — see note below)
- Tap-to-place manual landmarks, located by real CPU-side ray/triangle picking
  (Möller–Trumbore intersection) against the actual mesh geometry — not a screen-space guess
- Calibration: tap 2 points + enter a known mm distance → model-units-to-mm scale.
  Nothing assumes 1 model unit = 1 mm
- True 3D angle measurement: `acos(dot(A,B) / (|A||B|))` between two landmark-defined axis
  vectors, computed in actual 3D space — never from screen coordinates
- Optional projection onto sagittal / frontal / transverse planes (see coordinate convention
  note below)
- 3D distance measurement between any two landmarks, converted to mm once calibrated
- Deviation vs. a target/tolerance you enter, with PASS / near-tolerance / REVIEW status
- Save the full scan session (landmarks, calibration, all measurements) to a JSON file on
  device, in a schema shaped like the long-term Structural Twin scan object
- Real JUnit tests for the geometry engine (`AngleEngineTest`, `RayPickerTest`) — pure Kotlin,
  no emulator required, runnable with `./gradlew test`

**Explicitly NOT implemented — do not assume these exist:**
- Camera capture, AR/depth scanning, photogrammetry reconstruction (Stage 5–6)
- Automatic/AI landmark detection (Stage 7)
- Prescription/Standards engine as a persisted, configurable system (Stage 8) — target/
  tolerance are entered per-measurement for now
- Trimline as a 3D curve, cross-sections, original-vs-modified comparison, deviation maps
  (Stages 9–12)
- Any confidence scoring beyond "calibrated" / "not calibrated" — no invented percentages
- Orientation alignment tooling (aligning an arbitrary scan to a consistent anatomical
  coordinate frame). The sample test model is hand-authored already aligned to this app's
  Y-up convention; a real scan from Stage 5+ will need an orientation step before its
  angles mean anything

## Coordinate convention — read this before trusting any angle

This native app uses **Y-up**: X = medial/lateral, Y = vertical, Z = anterior/posterior —
standard for OpenGL and most OBJ-authoring tools.

The earlier CastIQ **web** prototype (`castiq3d.html`, Three.js) used **Z-up**: X = medial/
lateral, Y = anterior/posterior, Z = vertical.

**These are different axis mappings.** They are not yet reconciled. Per the directive's own
"IMPORTANT — SIGN CONVENTIONS" section, unifying this across CastIQ web, CastIQ native,
LayupIQ, and Structural Twin is real outstanding work, not a detail — don't assume a number
from one matches the same physical angle in the other without checking the convention first.

## About the sample test model

`sample_afo_cast.obj` is a small procedurally-generated solid (a tapered cylinder "leg" plus a
box "foot"), **not a real scanned cast and not anatomically accurate**. It exists purely so
Stage 1 has a genuine loadable, pickable, measurable 3D object to prove the engine against —
per the directive's own Stage 1 requirement to "load a known 3D test model" before camera work
begins. Its leg axis is exactly vertical by construction, which makes it a useful sanity check:
placing landmarks along it and measuring against vertical should read close to 0°.

Swap in a real scanned mesh (`.obj`) by replacing this file and updating the asset path in
`MainActivity.kt` — the rest of the pipeline doesn't care where the mesh came from.

## Important limitation on how this was built

This project was generated by Claude without access to the Android SDK, Gradle, an emulator,
or a physical device — it has **not been compiled or run**. The code follows standard,
well-established Android/OpenGL ES patterns, and the geometry math is covered by unit tests
you can read and verify by hand, but expect the possibility of a first-compile fix or two
(a missing import, a Gradle/AGP version mismatch with whatever Android Studio version you're
on, etc.). That's a normal part of opening a generated project for the first time, not a sign
the architecture is wrong.

## Building

### 1. Open the project
Open Android Studio → **Open** → select the `CastIQ3D-Android` folder (the one containing
`settings.gradle.kts`).

### 2. Gradle sync
Android Studio will prompt to sync automatically. If it complains about the Gradle wrapper
(the wrapper `.jar` binary isn't included in this generated project — only
`gradle-wrapper.properties`), let Android Studio regenerate it, or run:
```
gradle wrapper --gradle-version 8.7
```
once you have a system Gradle install, then re-open.

If Android Studio suggests updating the Android Gradle Plugin or Kotlin plugin version to
match your installed Studio version, accept it — the versions pinned here (`AGP 8.5.2`,
`Kotlin 1.9.24`) are a reasonable current baseline but Studio will know best for your setup.

### 3. Build a debug APK
```
./gradlew assembleDebug
```
Output: `app/build/outputs/apk/debug/app-debug.apk`

Or just click **Run ▶** in Android Studio with your Samsung device connected via USB
(with Developer Options → USB debugging enabled).

### 4. Install on your Samsung device
```
adb install app/build/outputs/apk/debug/app-debug.apk
```
Or use Android Studio's Run button directly — it installs and launches automatically.

### 5. Run the geometry engine unit tests
```
./gradlew test
```
These run on your development machine's JVM, no device or emulator needed — good first check
before touching a phone at all.

### 6. Release build (later)
```
./gradlew assembleRelease
```
You'll need to configure signing (`signingConfigs` in `app/build.gradle.kts`) before this
produces an installable release APK — not set up in this Stage 1 build.
